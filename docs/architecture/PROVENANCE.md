# Provenance index

Every tracked file in this repository has an origin and a maintenance state.
They are **orthogonal**, and conflating them was a real defect in the
reorganization plan's early drafts: "fork-authored", "generated" and "vendored"
are not alternatives to one another.

Derived from `config/move-manifest.yaml`, which is generated by
`build_move_manifest.py` from `git ls-files` and rename history. Nothing here is
maintained by hand.

---

## The two axes

```
origin      : upstream-valuenet | fork | external-bfo | external-cco
maintenance : unchanged | locally-modified | generated
```

`origin` answers *whose material is this*. `maintenance` answers *what has
happened to it here*. A file can be upstream-derived and generated; external and
unchanged; fork-authored and generated.

| origin | maintenance | files | example |
|---|---|---:|---|
| `upstream-valuenet` | `locally-modified` | 145 | the 124 repaired folk fragments |
| `fork` | `unchanged` | 116 | `marep/`, the BFO modules, the tests |
| `upstream-valuenet` | `unchanged` | 56 | `vale2024/`, the diagrams |
| `external-cco` | `generated` | 2 | the pinned CCO MIREOT extract |
| `external-bfo` | `unchanged` | 1 | `bfo-core.ttl` |
| `fork` | `generated` | 1 | `config/move-manifest.yaml` |
| | | **321** | |

## The rule that follows from it

**Anything whose origin is `upstream-valuenet` stays at its current path**,
whatever its maintenance state, documentation assets included.

`main` is 53 commits ahead of `upstream/main` and 0 behind. Retaining those
paths keeps the fork mergeable. Moving 145 locally-repaired upstream files would
raise conflict risk on every future merge, for tidiness.

That rule settles the cases that looked ambiguous:

| file | why it stays |
|---|---|
| `wvs.ttl` | renamed here from upstream's `wvs.owl` — origin is upstream |
| `ThatsAllFolks/folk.ttl` | converted from upstream `folk.owl`, RDF/XML to Turtle |
| `ThatsAllFolks/folk_Religion.ttl` | renamed from upstream `folk_Belief.ttl` |
| `ValueNet_stats.txt`, both `.png` diagrams | upstream, unchanged |

## Rename detection has a limit, and it is asserted

Origin follows `git log --follow`, not a comparison of current filename sets.
That comparison is what once classified `wvs.ttl` as fork-authored.

Two files descend from upstream by an edit large enough to defeat git's
similarity threshold, so their descent is **asserted** in
`KNOWN_UPSTREAM_DESCENT` with its reason:

| file | descent | why git cannot see it |
|---|---|---|
| `ThatsAllFolks/folk.ttl` | upstream `folk.owl` | RDF/XML → Turtle rewrote every line |
| `ThatsAllFolks/folk_Religion.ttl` | upstream `folk_Belief.ttl` | 623 trigger statements retargeted |

The alternative is a classifier that silently calls upstream content
fork-authored and then moves it.

## Generated artifacts

A generated file is never edited by hand; the generator is the source.

| artifact | generated from | generator |
|---|---|---|
| `folk_aligned.ttl` | `ThatsAllFolks/folk.ttl` | `generate_folk_aligned.py` |
| `BFO/imports/cco-valuenet-extract.ttl` | CCO 2.2 at a pinned commit | `generate_cco_extract.py` |
| `config/move-manifest.yaml` | `git ls-files` + rename history | `build_move_manifest.py` |

`folk_aligned.ttl` carries a `GENERATED FILE — DO NOT EDIT` header naming its
source and generator, and CI fails when it is stale. Its **canonical RDF digest**
is identical to its source's; its **byte hash** differs and will change again
when the generator moves, because the header embeds the generator's path. The
canonical digest is the invariant.
