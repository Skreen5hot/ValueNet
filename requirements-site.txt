# Pinned dependencies for the site build and the site tests.
#
# Only what the site build or site tests actually import -- verified by
# installing this file into an empty environment and running the suite
# there, which is how the first version of this file was found wrong.
#
# The build and the checker are standard library only. The tests are
# not, and by more than one link: they import marep.layout to resolve
# components through the layout contract, and importing anything from
# `marep` executes its package __init__, which loads the MAREP runtime
# and with it jsonschema. tests/conftest.py imports yaml directly.
#
# So a site test drags in the whole MAREP stack to ask the layout
# contract where a file is. That is worth knowing and is recorded
# here rather than hidden behind a wider pin; narrowing it means
# making marep.layout importable on its own, which is a change to
# marep and not to the site.
#
# Pinned exactly rather than with a floor: the point of a pinned file
# is that a clean environment reproduces this one, and ">=" reproduces
# whatever was newest that day.
#
# rdflib was scheduled to arrive with the Phase 3 class-index generator.
# It arrived earlier, with the catalog controls: asserting that every
# deliverable has one ontology header, one title, one description and the
# exact CC BY 4.0 IRI means parsing Turtle, and tests/site/test_catalog.py
# does. The alternative was to move that test out of tests/site purely to
# preserve the phase boundary, which would change canonical test
# identities and leave the dependency just as real.
#
# This file describes what the suite imports. It said otherwise for one
# commit, and the requirements-only gate is what found it.
#
# It is not, on its own, enough to run the suite. The class explorer's
# ranking ships as JavaScript, and tests/site/test_explorer.py tests it by
# running the file the browser loads rather than by re-implementing it in
# Python. That needs node, pinned in .nvmrc at the repository root -- the
# file nvm and actions/setup-node both read, so there is one version and
# not two.
#
# Node is a test dependency only. The site itself installs nothing: no
# npm packages, no build step, no bundler. Nothing here is a runtime
# dependency of the published pages.
#
# Absence of node fails the suite; it used to skip it, which is
# indistinguishable from a pass in every summary line.
