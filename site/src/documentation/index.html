Documentation

A reading path into the technical documentation and the validation evidence.

The documents below are in the project's repository, and each link opens one there, on the branch this site is built from. They are the working documents, not copies made for the site. They are listed in the order a new reader needs them, and this is a path through them rather than an index of everything.

1. Start with the model

The repository README
The shortest account of the core model, with a quick start and a table of the modules.
From description to reality
The rationale for the refactoring: why a value is modelled as something an agent bears rather than as a description, and what changed in structure and in axioms.
Original ValueNet
Where the original ValueNet material sits in this repository, and why it stays at the paths its authors use.

2. Use it

Annotation guide
A step-by-step process for annotating text: the action, the agent, the value, how they connect, and the words that are the evidence. With worked examples.
Competency questions
The questions the moral-epistemics module has to answer, each with its query and its result over a worked scenario.

The worked scenario is published with the modules, on the downloads page.

3. How it is checked

Testing framework
How the suite is tested by reasoner, by query and by manual review.
The test suite
The automated checks. Many re-derive a figure or a claim made in one of the documents on this page, so that a document cannot quietly stop being true.

4. The decisions

Decision records
Each modelling decision, with its rationale, its consequences and the condition that would reopen it. The table at the end says which are implemented.
RULES 2.0
The standard for definitions and annotations, recorded verbatim as received from the reviewer. The decision records say that it is adopted and how this project reads it.
Folk value membership
How membership of the folk module was decided: the criteria, the evidence, and the decision taken on each value.

5. The formal review

The suite was formally reviewed. What the reviewer wrote is recorded verbatim, and the records are listed in the order they were written.

The review
Recorded verbatim, with the commit it examined.
The response
What was done with it: each claim checked against the repository before it was accepted, and the places where the check disagreed.
The reviewer's sign-off
Sign-off on the response and on the plan for the remediation.
The update after the work
What was decided and done after that sign-off, written for the reviewer.
The reviewer's second sign-off
Confirmation of the sign-off, after the reviewer had read those later decisions.

A sign-off covers what had been decided when it was given. Anything decided later is in the decision records, each with the date it was adopted. The reviewer's intermediate replies sit beside these files, in the reviews directory.

6. What is still open

Open items
What is known to be unfinished or deliberately left, ordered by what should be done next. A test re-derives it from the repository, so an item that has been fixed cannot stay listed and a figure cannot go stale.

7. Evidence and provenance

Semantic baseline
What the current commit measures: a fingerprint of the whole corpus that reproduces from any checkout.
Transition matrix
The experiment that showed why earlier digests depended on where the repository was checked out.
Remediation record
Every repair made to the source data since that experiment, triple by triple.
Provenance index
Where every tracked file came from and how it is maintained.
Site quality report
This site's own gate: its links, its schemas, a build from a fresh clone, the browser review, and the owner's sign-off on what is published.

This evidence shows that the measurements reproduce and that the changes are accounted for. It does not show that the ontology is correct, complete, or validated against an external standard.

8. Terms and credit

Licensing
Which licence governs which part of the repository, and what neither project licence covers.
How to cite
The citation record for this suite. The original ValueNet is separate work and is cited separately in it.
Acknowledgments
Who and what contributed, in specific terms.
Third-party notices
The material this repository carries but did not author, and the terms each part is under.

9. Continuing the work

Handoff
For whoever picks the work up: where it stands, the conventions the tests enforce, and what to do first.
Publication plan
How this site is built, and what it may and may not claim.

Phase exit reviews, design notes and audit run records are the working history rather than the reading path. They stay in the repository, under the remediation records and the audit records.
